# 実装タスク: <機能名>

- 対応する設計: `./design.md`
- 進捗: 0 / N

## 凡例

- 1 タスク = 30〜90 分。テストまで含めて「動く状態」で終えられる粒度にする。
- 各タスクに「完了条件」と「関連する受け入れ基準(AC-x)」を書く。
- 完了したら `- [ ]` を `- [x]` にする。

## タスク一覧

### バックエンド

- [ ] **T-01: <タスク名>**
  - 変更対象: `backend/app/...`
  - 完了条件: <検証コマンドと期待結果。例: `uv run python -m pytest tests/test_x.py` が通る>
  - 関連 AC: AC-1

### フロントエンド

- [ ] **T-02: <タスク名>**
  - 変更対象: `frontend/lib/features/...`
  - 完了条件: `flutter analyze` と `flutter test` が通る
  - 関連 AC: AC-2

### 結合 / 仕上げ

- [ ] **T-03: 疎通確認**
  - 完了条件: `docker compose up` で起動し、受け入れ基準を手動で一通り確認できる
- [ ] **T-04: ドキュメント更新**
  - 完了条件: ルート `README.md` の機能一覧を更新し、`requirements.md` のステータスを `done` にする
